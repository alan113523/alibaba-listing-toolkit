# Alibaba Listing Toolkit

面向已授权 Alibaba.com 卖家会话的草稿和图片银行工具：把店铺身份、素材批准、写入意图和结果回读串在一起。

[English](README.md) · [API说明](docs/api.md) · [流程说明](docs/workflow.md) · [MIT许可证](LICENSE)

## 能力范围

- 相似品草稿创建、受保护字段继承、图片映射和回读比较。
- 图片银行的素材校验、映射复用、有界批量上传和未知结果对账。
- 分店身份绑定、写前持久意图、同一运行目录的重复写入拦截。
- 仅使用 Node 标准库；浏览器连接由有权使用的宿主环境提供。

公开版包含通用模块和流程说明。本机完整母版、质量审核及最终发布的业务批次脚本不随仓库发布；本项目也不自带浏览器启动器或 MCP Server。
这是非官方集成，使用卖家会话中的网页接口；接口、前端版本和类目模型变化时须重新验证。

## 先运行离线测试

需要 Node.js 22+、Git 和 npm，无需安装第三方依赖。

```sh
git clone https://github.com/alan113523/alibaba-listing-toolkit.git
cd alibaba-listing-toolkit
npm run check
npm test
```

测试在临时目录中生成虚构店铺配置和图片字节，通过内存 fetch/CDP 模拟响应，不读取你的真实配置、不登录平台、不上传或发品。

## 接入真实任务

1. 把两个模块的 bindings.example.json 分别复制到模块自己的 `.local/store-bindings.json`。
2. 填入经过独立核验的本机配置。示例中的空值不可直接使用，缺失或不完整时模块会停止。
3. 从宿主取得已授权的 CDP 句柄，按当前任务明确店铺、来源商品、数量、运行目录和允许动作。
4. 写前冻结请求并落盘意图，执行一次后读回；结果不明时使用原运行目录只读对账。

默认旧单条来源在本地配置中；新任务应显式指定本次来源，不能把历史母版当作永久默认授权。
主店可以处理 D 开头型号，其他店保留此限制；配置预期值不能替代当前 sellerProfileAjax 身份核验。

## 公开内容与隐私

真实账号、商品或图片 ID、原图、报价、完整表单、回执、运行目录和业务历史均未包含在仓库。
SAFE_FILES.txt 与 .gitignore 共同限制受控文件；新文件默认忽略，新增受控文件需要审查内容。
仓库恢复的是通用代码和说明，不能恢复你的业务环境或运行状态。

问题反馈请提供最小合成复现、Node 版本和脱敏错误码。完整数据契约和接口边界见 [API说明](docs/api.md)。
